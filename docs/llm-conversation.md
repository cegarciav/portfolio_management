● Agreed on all four. Details on each:

  1. Fractional shares: yes. A portfolio manager thinks in weights and money
  ("40% of the value in META"), not in share counts. Brokers and fund managers
  like Fintual also handle fractional quantities. Rounding to whole shares is a
  job for the part of the app that places the orders, because it depends on the
  broker's rules. The rebalancing logic should return the exact answer, and that
  layer rounds it. Two small consequences:
  - Precision. Dividing money by a price can give endless decimals, like 1/3.
    BigDecimal needs a precision for that, so we pick one, e.g. 10 decimal
    places, and document it.
  - Skipping tiny trades. Real apps usually skip trades that are too small to be
    worth making, often by only rebalancing when a stock drifts past some
    percentage from its target. I'd mention that in the README as a possible
    next step, not build it.

  2. Shares per stock: agreed. Shares are what you place an order with, and the
  money amount is just shares × price if someone needs it. I'd return a signed
  number per stock: positive means buy, negative means sell. I'd also include
  every stock from holdings and allocation, even when the answer is 0. That way
  the result always has the same keys, and the caller doesn't have to handle a
  missing stock.

  target_value(stock)  = (total_value + cash) × weight(stock)

❯ Any reason to use mise over rbenv?                                            

● For this repo the result is the same: both install Ruby from source and read
  .ruby-version. The difference is scope.

  rbenv
  - Manages Ruby only. It's the long-standing standard in the Ruby world, very
    mature, and widely documented.
  - Needs a plugin (ruby-build) to install Ruby versions.
  - Works by putting small wrapper commands in front of ruby, bundle and so on,
    which pick the right version.

  mise
  - One tool for many languages (Ruby, Python, Node, Go, …), configured per
    project.
  - It also reads files you may already have, like .ruby-version,
    .python-version and .nvmrc.
  - Works by switching your PATH when you enter a directory, so it adds no delay
    to each command.
  - It's newer, but widely used by now.

  My recommendation: you work with Python and have mobile/Node projects, and
  Fintual uses Ruby, Python, Go and Node. If you'd like one tool for all your
  language versions (replacing things like pyenv or nvm), choose mise. If you'd
  rather keep it minimal and Ruby-only, choose rbenv: it's the more conventional
  choice, and nothing in this project needs mise's extras.

  Which one should I use?
